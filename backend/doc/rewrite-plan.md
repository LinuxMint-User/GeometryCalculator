# 后端重写计划：TS 符号引擎

> 用 TypeScript 自研轻量符号计算引擎，替代 Python + SymPy 后端，实现全项目单一语言。

## 背景与动机

- **桥接开销**：pywebview 的 Python ↔ JS 桥接调用链长，交互效率低。
- **网页化成本高**：若迁移网页，Python 需 WASM（pyodide）编译，链路复杂。
- **依赖过重**：当前仅用到 SymPy 一小部分功能（表达式、方程组求解、化简、假设、LaTeX 打印），背一个约 50 万行的库不划算。
- **代码洁癖**：项目内语言种类越少越好，除非遇到性能瓶颈。

## 总体原则：三分区

把符号计算从「数学问题」降维成「工程问题」，核心是两条原则：

1. **匹配不上就投降**：符号推导做不了立刻转数值，绝不硬解。
2. **红灯区写进文档**：明确告知「我不干」，是健康的产品边界。

| 分区 | 态度 | 手段 |
|---|---|---|
| 🟢 绿灯区 | 核心支持，全力符号化简 | AST 精确处理 |
| 🟡 黄灯区 | 数值兜底，绝不死磕符号 | 标准数值算法 |
| 🔴 红灯区 | 明确拒绝，报错或转数值 | 文档化边界 |

## 分区细则

### 🟢 绿灯区（符号化简）

- **运算符**：`+`、`-`、`*`、`/`（保留分数形式）、`^`（整数次幂）。
- **初等函数**（仅用于求导/模板匹配）：`sin`、`cos`、`tan`、`exp`、`ln`。积分遇到它们若匹配不上模板，立刻转数值。
- **常数**：`e`、`π` 作为符号兜着，运算时保留，仅在最终求值时转为小数。
- **代数数（输出专用）**：仅支持 `a + b√c` 形式（`c` 为无平方因子整数）。这是初高中几何的极限；`√2 + √3` 这类直接算小数，不强行合并。
- **`sqrt` 是绿灯区公民**：几何引擎（距离、面积公式）天然产生平方根。
  - `sqrt(k²·c) → k·sqrt(c)`（提取平方因子，保证 `c` 无平方因子）
  - `k₁·sqrt(c) + k₂·sqrt(c) → (k₁+k₂)·sqrt(c)`（同类根式合并）
  - 出现不同根式（写不出 `a+b√c`）→ 转数值
- **符号假设**：Symbol 挂 `sign` 标签（正/非负/负/非正/非零），求根后筛根（如 `a²=1` 且 `a` 为正 → 只给 `a=1`）。不做复杂假设系统。

### 🟡 黄灯区（数值兜底）

- **积分**：匹配不上模板（如 `xⁿ`、`sin`、`f'/f`）时，直接调用辛普森 / 高斯-勒让德数值积分，返回 `number`。
- **方程求根**：
  - 一元，3 次及以上或含超越项 → 牛顿法 / 二分法，返回 `number[]`。
  - **多变量方程组 → 多维牛顿法**（雅可比矩阵迭代），作为方程组默认数值求解器。
  - 不实现通用根式公式。
- **线性代数**：行列式、求逆内部全用分数（Fraction）或浮点数计算，不保留符号参数。矩阵元素必须是具体数字；输入含符号（如 `[[a, b], [c, d]]`）直接报错「不支持符号矩阵」。

### 🔴 红灯区（明确拒绝）

- **不定积分**：拒绝求闭式解，除非匹配查表。
- **微分方程解析解（ODE）**：完全不支持（预留数值解接口，第一版不接入口）。
- **含符号参数的多项式因式分解**（如 `xⁿ - aⁿ`）：不处理，只对整数系数且次数 ≤ 4 的做因式分解。
- **通用三角化简**（`TrigReduce`）：不实现，只写死 10~20 条高频规则（如 `sin²x + cos²x = 1`、倍角、诱导公式）。

## 模块架构

```
src/core/
├── expr.ts        # 表达式树：Add / Mul / Pow / Symbol / Number / sqrt / 函数
├── parse.ts       # 用户输入 → 表达式树
├── simplify.ts    # 化简：合并同类项、有理数、0/1 归约、三角规则表
├── poly.ts        # 多项式代数：GCD、因式分解（整数系数 ≤ 4 次）、一元求根
├── solve.ts       # 方程组：线性部分 Gaussian 消元 + 代换 + 一元求根 / 多维牛顿
├── numeric.ts     # 数值兜底：一元高次求根、多维牛顿、数值积分（辛普森 / 高斯-勒让德）
└── latex.ts       # 表达式 → LaTeX（对接前端 KaTeX）
```

几何对象（点、直线、距离、斜率、面积、角度）用初等解析几何公式自算，不依赖任何库。

## 求解策略

1. 几何约束（距离、斜率、垂直、平行、全等、相似、平行四边形等）生成**多项式方程**——这是主战场，用消元 + 求根。
2. 用户手输表达式（可能含 `sin`、`sqrt`、`ln`）——模板匹配优先，失败转数值。
3. 求解结果：
   - 能写成 `a + b√c` → 符号输出。
   - 否则 → 数值解（保留若干位小数），标注近似。
4. 符号假设（`sign` 标签）在求根后筛根。

## 迁移路径（分期，每期可独立验证）

| 阶段 | 内容 | 替换对象 |
|---|---|---|
| P1 | 表达式树 + 解析 + 化简 + LaTeX 打印 | `to_raw_latex`（显示层先脱离 Python） |
| P2 | 多项式运算 + 一元求根（公式法） | 一元方程求解 |
| P3 | 多变量消元（线性 Gaussian + 代换） | 几何约束方程组求解 |
| P4 | 符号假设（sign 标签）+ 数值兜底（多维牛顿、积分） | `solve` 完整替换 |

前端 `state.js` 已是现成的对象状态容器（未知数 / 点 / 条件），直接作为 `math_objs` 的替代品。桥接层在全部替换完成后拆除。

## 验证与测试

- 用文档（guide）中的例题做黄金测试集：斜率、截距、点到直线距离、全等 / 相似、平行四边形等。
- 每个阶段配独立测试，回归时快速定位。
- 数值解标注近似，与符号解输出明确区分。
